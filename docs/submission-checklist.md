# Чеклист готовности к сдаче

## Основа проверки

Команде предоставлено задание TASK-2 на README, схему решения и сценарий демо. Оно задаёт требования к этим артефактам, но не заменяет полное бизнес-ТЗ кейса. Документация для схемы и демо уже есть: [docs/architecture.md](architecture.md) и [docs/demo.md](demo.md).

При этом [case/case.md](../case/case.md) всё ещё содержит шаблонное «Кейс ещё не выдан». Это рассинхрон репозитория с полученным заданием: бизнес-контекст и ограничения AML-кейса не внесены в файл, хотя часть фактов отражена в документации и данных. Перед сдачей нужно сверить и синхронизировать описание кейса; сам `case/case.md` в рамках этой правки не меняется.

## Проверка текущей версии

`tests/final_check.sh` клонирует ветку `main` с `origin` во временную папку и проверяет именно этот удалённый снимок. Скрипт не тестирует незакоммиченные изменения текущего рабочего каталога; незапушенная версия попадёт в прогон только после публикации в удалённом `main`. В нём девять пунктов: clone, venv, установка зависимостей, пайплайн с лимитом 300 секунд, проверка выходных файлов, тесты пайплайна, UI smoke, отсутствие `.env` и поиск секретоподобных ключей среди tracked-файлов.

Для ревизии `4f9795f` в изолированной копии с уже подготовленным окружением Python 3.14.2 пайплайн завершился за 1,7 с; пайплайн сформировал 91 кластер, а `tests/check_outputs.py` подтвердил схему на 2 248 узлах и топ-30; `tests/test_pipeline.py` прошёл (2 теста, 4,064 с); UI smoke прошёл для обоих UI; `tests/smoke_test.py` прошёл. Дополнительный AppTest главной вкладки подтвердил топ-10, открытие карточки лидера, три GID демо, предупреждение P-trunc и сброс. Это не свежая установка зависимостей и не прогон `tests/final_check.sh`; браузерный рендер и живой LLM также не проверялись. Сам `final_check.sh` не запускает `run.sh` и не подтверждает полный ручной сценарий демонстрации.

Запуск проверки удалённой версии из корня репозитория (нужен интернет для клонирования и установки пакетов):

```bash
bash tests/final_check.sh
```

## Перед сдачей

- Внести в `case/case.md` бизнес-контекст и ограничения AML-кейса; задание TASK-2 покрывает README/схему/демо, но не является полным описанием предметной области.
- Запустить проверки после интеграции финальных изменений и сохранить результат вместе с SHA коммита, который реально проверен удалённым `origin/main`.
- Убедиться, что нужная версия документации и скриптов запушена в `main`, прежде чем трактовать `tests/final_check.sh` как проверку поставляемой версии.
- Провести ручную репетицию по [docs/demo.md](demo.md); не представлять ответы модели или офлайн-рендер графа как проверенные, если их не запускали в целевой среде.
